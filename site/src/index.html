Lodestone keeps

somewhere that works.

A small TypeScript library that sits between your tool and AI models. When a model is withdrawn, slow, rate-limited or down, it moves to the next one, stays inside your time limit, spends only what you allow, and, if everything fails, tells the person what went wrong in plain words.

01 · The problem

Six ways a cheap AI call breaks

Free and low-cost models come and go, and gateways have bad days. Every tool that calls them ends up rewriting the same defensive code. Lodestone does it once, for all your tools.

The model disappears

A hard-coded model id stops working without warning when the provider withdraws it.

FixYour list is a preference, checked against the provider's live catalogue. Gone or retiring models are dropped and replaced.

One model eats the clock

A single slow model uses the whole serverless time limit and the person sees an unreadable gateway error.

FixEach attempt gets a slice of a 24 s budget (under a 30 s gateway). A slow model is cut off and the next one tried.

"429" means four things

Daily limit, per-minute limit, busy upstream, or no credit. Each needs a different message to the person.

FixFailures become typed errors, and explain() turns each into advice a person can act on.

The provider itself is down

One gateway's outage takes every model behind it, and every tool that depends on it.

FixFallback providers, each with its own key: Requesty, LLM API, Groq and others. An outage cannot use up the whole time budget before they get a turn.

The same dead model, every time

Free models fail in bursts, and without memory every request pays to find out again.

FixA circuit breaker, shared across functions, skips a model that keeps failing and lets one attempt through every two minutes to see if it is back.

"Free" is not free if it hangs

A paid fallback with no limit is risky on a public tool, and free models that never answer cost your users time.

FixPaid-first on your own key, free as the backup, and a spend hook that stops paid calls at a daily or monthly limit.

03 · Measured, not assumed

What one bad day looked like

On 28 October 2026 the free OpenRouter models behind a real tool stopped answering, and scoring a job posting ran its whole 24 s budget and failed. These are the measurements that changed how Lodestone's defaults work. One day, one posting and one CV, so read them as an example, not a benchmark.

Free models

1 usable answer in 15 attempts

Three attempts each on five free models. Two were rate-limited every time (429), two held the connection open for 45 s and never answered, and the router once chose a safety classifier that replied "User Safety: safe". The one good answer took 25 s.

Paid models

About 3 s, for under a tenth of a cent

Reading a posting: claude-haiku-5.5 took 3.0–3.2 s in all three runs for $0.0004. Scoring took about 5 s. Gemini was 5–6 s; Mistral Small was erratic (7–9 s, and one rate limit).

A mistake worth owning

Time until the whole answer

My first speed table timed only until the response headers arrived, which made every model look much faster. OpenRouter sends headers early and the body follows seconds later. Lodestone's own tests and tools now time the full body.

So reasoning is set per model (openrouter({ reasoning })), a paid-first mode exists (paidFirst), and the free models become the backup. The result for that tool: reading a posting in 2.6–3.1 s and scoring in 4.5–4.9 s, instead of failing after 24 s.

05 · Lists that keep themselves alive, short and safe

Discovery that never makes a request slower

A model list that nobody edits goes stale; one that fills itself can grow until it is slow, or admit something you would not choose. Lodestone does the first and bounds the second.

Alive

Outdated models drop out

A daily checkModels() saves each provider's catalogue. A model it no longer lists is dropped. One with an expiry date within a week is left out (OpenRouter publishes the date; 14 models carried one the day this was written). One failing right now is skipped by the breaker.

Short

A pool of 8, three tried

The ranked pool lives in the background. Models that are down are filtered out, and a request tries at most three. When one fails, the next best takes its place for later requests, so adding models adds choice, not delay.

Safe

Trust is checked, not assumed

A discovered model must come from a trusted lab. You can block labs or models, refuse any a provider says is trained on or keeps prompts too long, and mark a single call private.

What the trust policy decides

Verdicts are computed by the library's own vet() as this page is built, on rows shaped like real lists. On 28 Oct 2026, of Requesty's 807 chat models, 205 came from a lab not on the default list and 9 were marked as trained on. LLM API publishes nothing about what happens to prompts, so under a strict policy none of its models can be discovered; models you name yourself still work.

What this is not. There is no vulnerability database for hosted AI models, so Lodestone does not claim to scan one. It checks what providers actually publish, and enforces your rules on it. Those facts are self-reported by providers. SECURITY.md lists exactly what is and is not checked.

06 · When everything fails

Eleven kinds of failure, each with its own advice

complete() and json() throw a LodestoneError with one of these kind values. Tap one to read the sentence explain(err, { product: 'MyApp', settingsHint: 'in Settings' }) gives a person.

The sentences are the library's own: this page calls explain() for each kind when it is built, so they cannot drift from the code.

07 · Getting smarter over time

Scorecards: let measurements choose the order

Two small JSON formats let an evaluator and Lodestone feed each other without sharing code. Naija Eval, which measures translation and speech quality for Hausa, Igbo and Yoruba, is the first to use them. Its scores are translation quality, so they help tasks in those languages, not every task.

Evaluator (Naija Eval)

Measures answer quality, such as chrF++ for English→Yoruba, per model.

model-scorecard/1 →
← model-candidates/1
← live reliability

Lodestone (in your tool)

Tries the best-measured models first for tasks you name, lists the models it can call, and records its own success rates and speeds.

  • A scorecard only changes the order models are tried in. Nothing is added or dropped.
  • Scores from fewer than 30 items, or over a year old, are ignored.
  • Unmeasured models keep their slot, so a good unmeasured model is never pushed down.
  • An explicit route is never reordered.
  • If the scorecard fetch fails or takes over 1.5 s, the order is left alone.
  • Live stats keep the last 200 attempts per model and never see prompts or answers.
08 · Using it

What a tool writes

// set up once, and share the store
const ai = createLodestone({
  openrouter: { apiKey: OPENROUTER_KEY,
    allowPaid: true, paidFirst: true,
    paidModels: ['anthropic/claude-haiku-5.5'],
    reasoning: (m) => m.startsWith('anthropic/')
      ? { enabled: false } : { effort: 'low', exclude: true } },
  fallbacks: [
    { provider: requesty(), apiKey: REQUESTY_KEY,
      models: ['bedrock/claude-haiku-5-5'],
      discover: { fill: { maxPromptUsdPerMTok: 1,
                          maxCompletionUsdPerMTok: 5 } } },
    { provider: groq(), apiKey: GROQ_KEY,
      models: ['llama-3.3-70b-versatile'], free: true },
  ],
  store, health: createHealth({ store }),
  spend: { allow: underDailyLimit, record: addToLedger },
  trust: { requireNoTraining: true },
});

// each call names a task, not a model
try {
  const { data } = await ai.json({
    prompt, validate: isJob, signal: req.signal,
    private: true });   // a CV: do not keep or train on it
} catch (err) {
  return explain(err, { product: 'MyApp' });
}
  1. Tiers, not model ids. A task maps to fast, strong or vision (picked automatically when a message has an image). Or pass a fixed route to name provider, model and key yourself.
  2. Customer keys stay separate. A caller's own key replaces yours and unlocks the paid model, but your fallback providers and your spend ledger are never touched by that call.
  3. Daily upkeep. checkModels() refreshes every provider's catalogue and reports what has gone or is retiring. cacheKey and peek() reuse answers for repeatable tasks.
  4. Cancelling. Pass a signal; when the person leaves, the call and every model after it stop.
  5. Private by design. onAttempt reports provider, model, outcome and timing only. Prompts and answers are never logged.
09 · Honest limits

What it does not do yet

Streaming

complete() and json() wait for the whole answer. Streaming needs a rule for a model that fails halfway; the likely one is to fail over only before the first token.

Tool calling, embeddings, speech

Lodestone is for one-shot text and JSON calls today. It does not let a model call functions, and it has no tier for embeddings or speech.

Other runtimes

It uses only fetch, AbortSignal and URL, with no Node-specific APIs, so it should run on Workers, Deno and edge runtimes. It has only been tested on Node 20 and 22.
